# 05 · 协作协议（怎么干活）

## 一、一句话
**PM 拆活派活，工人只干一件，审查员只认证据；一轮过闸再下一轮。**

## 二、角色与边界
- **PM**：维护 `02-任务板`；为每个任务写专业提示词（含背景、范围、验收标准、禁止项）；启动工人；收集产物；发起审查；按结论更新板子；向用户汇报。**不亲手改业务代码**。
- **工人**：单任务、单目录；交付物 + 自检证据；**不得自称"已完成"作为验收依据**；越界发现的问题只记录，不顺手改。
- **审查员**：独立会话、**不同模型**；只读文件与证据；输出 `PASS`/`FAIL` + 依据；**不帮忙修**。

## 三、启动工人的标准命令（Windows）

> **2026-11-23 实测修正**：`--permission-mode always_allow` 已被 CLI 拒绝（invalid_arguments: 所选权限模式不可用），改用 `--dangerously-bypass-approvals-and-sandbox`（二者互斥）。三个必守细节：
> 1. **stdin 必须立即 EOF**：用 `$null | & doubao.cmd ...`。后台壳的 stdin 是不关闭的管道，`-p` 会死等管道输入（曾卡死 50 分钟不建会话）。
> 2. **Start-Process -File 的脚本路径不能含空格**（参数会被截断静默失败）；派活脚本放 `evidence-round<N>/` 等无空格路径。
> 3. 重定向逻辑 `*> log` 首行是 `{"type":"session","session_id":...}`，会话 ID 据此核对；控制台中文可能 GBK 乱码，**以产物文件（UTF-8）为准**。

```powershell
# 执行者（示例：DeepSeek V4.1 Flash；模型 ID 以 doubao model list 实测为准）
$null | & C:\Users\Challenge\AppData\Roaming\npm\doubao.cmd -C "D:\Project\OpenSourcePlan\ChallengeDaily20260703\ChallengeDaily" `
  --model "person-deepseek-v4-1-flash-261017" --effort high --dangerously-bypass-approvals-and-sandbox `
  --output-format text -p "<提示词>" *> <无空格路径\worker.log>

# 审查者（示例：豆包 2.1 Lite = seed-lite-7b，独立会话）
$null | & C:\Users\Challenge\AppData\Roaming\npm\doubao.cmd -C "<同一目录>" `
  --model "seed-lite-7b" --effort high --dangerously-bypass-approvals-and-sandbox `
  --output-format text -p "<审查提示词：只验证据，输出 PASS/FAIL>" *> <无空格路径\review.log>
```
- 需要**看得见**：把命令放进可见窗口运行（PM 用 `Start-Process pwsh -NoExit` 起脚本，窗标题写角色）
- 需要**返工**：`--resume <会话ID> -p "审查意见 + 要求"`，保留原会话记忆，不重头来（resume 不必再传 --model）
- 可用模型：`doubao model list`（2.1 Pro 仅 low/medium/high，别给 max）
- 派活后**验证会话真创建**：查 `%LOCALAPPDATA%\doubao_cli\agent_mode\<账号ID>\workspace\.sessions\` 新目录的 assignment.md 是否含本任务编号，别只看进程活着

## 四、提示词模板（PM 用）
```
【任务】<编号+标题>
【目标】<一句话>
【范围】只许改：<文件列表>；不许动：<禁止项>
【参考】docs/memory/01、02、最近一条 03
【验收】<可执行/可核对的硬标准：测试通过、命令输出、文件内容、diff>
【证据】把执行命令与输出贴在最终回复里
【约束】最小修改；Python 改完跑 py_compile；不新增依赖；不提交 git
```

## 五、审查提示词模板
```
你是独立验收员，没看过执行者的自述。只依据实际证据判断：
1) 读 <文件/跑 <命令>；2) 对照验收标准逐条核；3) 检查是否越界改动（git diff）。
输出：第一行只写 PASS 或 FAIL；之后逐条给证据（实际读到的内容/命令输出）。
```

## 六、日志与证据
- 每轮结束：PM 追加 `03-轮次日志`；更新 `02-任务板`
- 证据存放：`evidence-round<N>/`（截图、命令输出、日志）
- 提交：`round<N>: <一句话> (vX.Y.Z)`，推送 origin/gitee/gitcode

## 七、红线
- 不虚报完成；不带 FAIL 进下一轮
- 不改 `.env`、不改既有 API 响应格式、不删端点
- 不经用户同意不动 git 历史、不 force push
