# 04 · 决策记录（ADR）

> 只记"为什么这么定"，不记执行过程。执行过程在 03-轮次日志。
> 状态：`已采纳` / `已废弃` / `待评估`

## ADR-001 · 项目记忆落盘，不依赖模型上下文
- 日期：2026-11-22
- 背景：单个会话上下文有限，长项目必然遗忘；换 Agent 后历史断层
- 决策：所有目标、任务、进度、决策、协作规范写入 `docs/memory/`；任何 Agent 读文件接手
- 取舍：多花维护文件的力气，换来不丢记忆、可回滚、可换人
- 状态：已采纳

## ADR-002 · 分轮 + 闸门 + 独立对抗审查（拒绝"一次性多子智能体"）
- 日期：2026-11-22
- 背景：一次性塞大计划让 AI 自动委派一堆子智能体，结果质量差、无法验收
- 决策：一次只开一个任务；执行与审查分离；审查独立会话 + 换模型；只看证据
- 取舍：慢一点（每轮多一次审查），换来可控、可追责、质量稳定
- 状态：已采纳

## ADR-003 · 模型分工：豆包当主力，别家只做关键节点第二意见
- 日期：2026-11-22
- 背景：豆包额度充裕，qoder/codebuddy 额度少
- 决策：执行用 `Doubao 2.1 Pro`（或 `Qwen 4 Max`）；日常审查用 `DeepSeek V4 Pro`（同额度、异模型）；大版本发布前可用别家 CLI 做一次跨厂商抽查
- 状态：已采纳

## ADR-004 · 审查必须产出 PASS/FAIL + 证据，不接受"我觉得没问题"
- 日期：2026-11-22
- 决策：审查输出固定格式第一行 PASS/FAIL，其后附实际读取/执行结果
- 状态：已采纳
