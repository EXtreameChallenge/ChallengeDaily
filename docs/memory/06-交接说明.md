# 06 · 交接说明（新 Agent 3 分钟上手）

## 一、你是谁
你很可能是被拉来当 PM、工人或审查员的临时 AI。**不要靠猜**：项目所有事实都在磁盘上。

## 二、按顺序读（不要跳）
1. `AGENTS.md`（根目录）：铁律 + 角色 + 目录地图
2. `docs/memory/01-项目总览.md`：项目是什么、怎么跑
3. `docs/memory/02-任务板.md`：现在该干什么（只认 `doing`/`todo`）
4. `docs/memory/03-轮次日志.md` 最后 2 条：最近发生了什么
5. `docs/memory/04-决策记录.md`：为什么这么定（别推翻已采纳的决策）
6. `docs/memory/05-协作协议.md`：怎么派活、怎么写提示词、怎么审查

## 三、接手 PM 的动作
1. 先只读，不改任何代码
2. 输出「接手理解」：当前版本、当前轮次、任务板状态、风险点、下一步建议
3. 等用户确认后再派第一个任务
4. 每轮结束必须：更新任务板 → 追加轮次日志 → bump 版本 → 提交推送

## 四、回滚（出事了怎么办）
```powershell
git -C "D:\Project\OpenSourcePlan\ChallengeDaily20260703\ChallengeDaily" log --oneline -10
git -C ... diff <commit> -- <file>          # 看某个提交改了什么
git -C ... checkout <commit> -- <file>      # 单文件回到某个版本
git -C ... revert <commit>                  # 整提交回退（推荐，保留历史）
```
**原则**：优先 `revert`，不重写历史、不 force push。

## 七、已知环境坑（2026-11-22 实测）
- **豆包桌面会话内 git 锁问题**：文件保护会拦截 `.git/*.lock` 的删除，且 git 自身收尾改名会留下锁。症状：`index.lock exists` 反复出现。解法：用 `Move-Item` 把锁**移走**（改名可行、删除被拦），并在 add/commit/push **每步之后**清锁；提交加 `-c gc.auto=0`。CLI 工人自己的终端一般无此问题。
- GitHub 推送偶发 Connection reset，重试即可；三远端以 `git ls-remote` 核对同 hash 为准。

## 八、CLI 派活坑（2026-11-23 R15 实测，详见 05 §三）
- `--permission-mode always_allow` 已不可用 → 改 `--dangerously-bypass-approvals-and-sandbox`。
- `-p` 模式 stdin 是管道时会死等输入：必须 `$null | & doubao.cmd ...` 给立即 EOF，否则进程活着但永不建会话。
- `Start-Process pwsh -File <含空格路径>` 参数截断静默失败：派活脚本放无空格路径（如 evidence-round<N>/）。
- 执行机可能睡眠/重启导致离线、工人进程被杀：派活后核对会话 assignment.md 含任务编号；工人死了用 `--resume <会话ID>` 续，不重头来。
- 工人日志控制台中文可能 GBK 乱码，产物文件 UTF-8 为准；log 首行 JSON 给会话 ID。
