## 一、问题诊断：为什么现在感觉"散"

### 1.1 三个具体症状

**症状一：入口平铺，没有叙事线**

当前 40+ 页面在侧边栏中是并列关系。用户打开应用看到的是"功能列表"，而不是"我现在该做什么"。这在认知科学中称为**外在认知负荷（Extraneous Cognitive Load）**——信息呈现方式本身消耗了用户本应用于核心任务的认知资源。

**症状二：功能之间断裂，用户需要自己"找下一步"**

用户的真实行为是连续的：看日报发现问题 → 想改进 → 设番茄钟 → 执行 → 复盘。但当前设计中，这五步分散在五个独立页面，每一步都要用户自己想"接下来该去哪"。这违背了**执行意图（Implementation Intentions）**理论——人在"如果X发生，我就做Y"的结构下行动率远高于"我要做Y"，而当前系统没有提供这个"如果…就…"的衔接。

**症状三：AI 是孤岛，不是助手**

AIChat 是一个独立页面，用户必须主动切换过去。但真正的助手应该在用户需要的时刻出现在上下文中——看日报时直接点评，分心时直接提醒，完成任务时直接给反馈。

### 1.2 根本原因

当前架构是**"以功能为中心"**组织的：每个功能模块独立开发、独立入口、独立数据。而用户体验需要的是**"以场景为中心"**组织：围绕"早晨开机→上午专注→午休→下午工作→晚上复盘"这条时间线，功能在需要时自然出现。

## 二、设计哲学：科学依据与设计原则

### 2.1 核心科学理论框架

本方案的每一个设计决策都基于以下经过验证的行为科学理论：

| 理论 | 提出者 | 核心观点 | 在本方案中的应用 |
|------|--------|----------|-----------------|
| **习惯回路** | Charles Duhigg | 提示→行为→奖赏，三者闭环形成习惯 | 自动采集是"提示"，接力链引导"行为"，成就反馈是"奖赏" |
| **执行意图** | Peter Gollwitzer | "如果X发生，我就做Y"比"我要做Y"执行率高2-3倍 | 每个接力链都是"如果…就…"结构，系统主动提供下一步 |
| **注意力残留** | Sophie Leroy | 任务切换后注意力仍部分停留在旧任务，需15-25分钟恢复 | 番茄钟锁定25分钟、屏蔽干扰、减少切换 |
| **认知负荷理论** | John Sweller | 外在认知负荷越低，用于核心任务的认知资源越多 | 主页按时间线组织，减少"找功能"的负荷 |
| **决策疲劳** | Roy Baumeister | 决策数量越多，每个决策质量越低 | 系统推荐下一步，减少"该干什么"的决策消耗 |
| **心流理论** | Mihaly Csikszentmihalyi | 挑战与技能匹配、目标明确、即时反馈时进入心流 | 番茄钟+待办关联+实时进度+宠物反馈 |
| **自我决定理论** | Deci & Ryan | 自主感、胜任感、归属感是内在动机的三大支柱 | AI建议而非强制（自主）、进度可视化（胜任）、排行榜/自习室（归属） |
| **BJ Fogg 行为模型** | BJ Fogg | 行为=动机×能力×提示，三者缺一不可 | 自动采集降低能力门槛、数据洞察提供动机、宠物/AI提供提示 |
| **峰终定律** | Daniel Kahneman | 人对体验的记忆由"峰值"和"终点"决定 | 晨报洞察（峰）、晚间日报+成就（终）是关键设计节点 |
| **时间贴现** | 行为经济学 | 人倾向于低估未来回报，高估即时满足 | 即时反馈（宠物/番茄钟倒计时）优先于长期目标 |
| **计划谬误** | Kahneman & Tversky | 人系统性低估任务完成时间 | AI基于历史数据估时，纠正乐观偏差 |
| **蔡格尼克效应** | Bluma Zeigarnik | 未完成任务在脑中持续占用注意力 | 待办清单+进度条让未完成事项"外化"，释放大脑内存 |

### 2.2 五条设计原则

基于以上理论，本方案遵循五条设计原则：

**原则一：时间线即界面（Timeline as Interface）**
> 人的一天是线性的，界面也应该是线性的。不要让用户在功能树中导航，让他们在时间线上自然流动。

**原则二：下一步永远可见（Next Action Always Visible）**
> 任何时刻，用户都应该看到"接下来做什么"的建议。这不是强制，而是降低决策疲劳。参考 GTD 的"下一步行动"概念和执行意图理论。

**原则三：数据指向行动（Data Leads to Action）**
> 每一个数据展示点都应该有一个对应的行动入口。看到"微信2.3小时"不应该只是焦虑，应该立刻能"设个番茄钟屏蔽微信"。

**原则四：AI 是上下文，不是页面（AI is Context, Not a Page）**
> AI 不应该是一个需要切换过去的页面，而应该渗透在每个场景中。用户不需要"打开AI"，AI就在他看数据、做计划、执行任务的时刻出现。

**原则五：反馈即时且分层（Feedback is Instant and Layered）**
> 不同时间尺度需要不同反馈：秒级（宠物状态）、分钟级（番茄钟进度）、日级（日报）、周级（深度洞察）。每一层反馈都为下一层积累动机。

## 三、产品叙事重构：一天的旅程

### 3.1 核心叙事线

ChallengeDaily 不再是"一个有很多功能的软件"，而是**"一个陪你度过每一天的AI伙伴"**。它的叙事线是：

```
早晨：帮你看清今天 → 白天：陪你专注执行 → 晚上：帮你复盘成长
```

所有功能都在这条叙事线上找到自己的位置，没有"多余的功能"，只有"还没到出场时间的功能"。

### 3.2 完整用户旅程地图

**科学依据：**
- **心流理论**：25分钟锁定+屏蔽干扰+明确目标，创造心流条件

- **即时反馈**：番茄钟倒计时、宠物状态、专注质量评分都是即时反馈
- **胜任感**：完成时的"比预估快"反馈增强胜任感（自我决定理论）
- **蔡格尼克效应**：完成任务后自动提示下一步，不让"接下来干什么"占用大脑

- **成长型思维**：建议用"下次可以试试"而非"你不应该"，培养成长型思维
- **蔡格尼克效应**：明日计划让未完成的事情"外化"到系统中，大脑可以真正休息
- **日记的心理价值**：表达性写作（Expressive Writing）被证明能降低焦虑、提升睡眠质量。AI预填数据降低了写日记的启动门槛
- **进度反馈**：与昨天/上周对比的百分比（+12%）提供胜任感

今日主页是整个重构的核心。它不是一个静态仪表盘，而是一个**随时间流动的、有生命的界面**。

### 5.1 页面结构

### 5.2 时间线设计

时间线是主页的核心组件，它把"已发生的活动"和"计划的任务"融合在一条线上：

```
        已过时段                    现在          未来时段
  ────────────────────────┃─────────────────────────
  灰色，可回看              🔵 高亮        虚线，显示计划
  自动采集数据              实时状态       用户排期的任务
  AI摘要+类别色             当前活动       预估时长
                           正在执行的番茄钟

  09:00 ─ 🔴 重构登录模块
  09:25 ─ ☕ 休息
  09:30 ─ 🔴 重构登录模块
  10:00 ─ 💬 站会
  10:30 ─ 🔴 重构登录模块 ✓完成
  11:00 ─ 🟡 回复PR ─────── 🔵 11:25 现在
  11:30 ─ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄ ┄
  12:00 ┄ ┄ 😴 午休（计划）
  14:00 ┄ ┄ 🟢 写周报（计划）
  15:00 ┄ ┄ 💬 评审会议（日历同步）
```

**交互设计：**
- **点击已过时段**：展开详情卡片，显示该时段的应用使用、AI摘要、相关任务
- **点击未来任务**：弹出任务详情，可以编辑、推迟、开始
- **拖拽未来任务**：可以在时间线上重新排期
- **时间线自动滚动**：当前时间线始终保持在视口中央偏上位置
- **SSE实时更新**：新的活动记录自动插入时间线，无需刷新

### 5.3 动态卡片区

动态卡片区是"功能接力"的主要发生地。它根据当前时间和状态显示不同的卡片：

**早晨卡片序列（07:00-09:00）：**

1. **晨报卡片**（首次打开时显示）
   - 昨日数据摘要 + 今日AI建议 + 日历事件
   - 主按钮：[开始今天的计划]
   - 点击后滚动到今日计划卡片

2. **今日计划卡片**
   - 从周计划拉入的任务 + AI建议优先级
   - 每个任务有[▶ 开始]按钮（接力到番茄钟）
   - 支持[+ 添加任务]和[从周计划拉入]

3. **晨间习惯卡片**
   - 今日习惯打卡
   - 打卡后宠物给即时反馈

**白天卡片序列（09:00-18:00）：**

4. **番茄钟卡片**（任务进行中）
   - 倒计时 + 当前任务 + 专注质量
   - 暂停/结束/加时按钮
   - 结束后自动切换到"番茄钟完成"卡片

5. **番茄钟完成卡片**（过渡态）
   - 专注质量评分 + 休息/继续/完成任务
   - 点击[完成任务]自动标记待办并提示下一个

6. **接下来卡片**（任务间隙）
   - 下一个任务建议 + 即将到来的日历事件
   - [▶ 开始下一个] 一键接力

7. **AI教练提醒卡片**（条件触发）
   - 分心提醒、低谷建议、休息提醒
   - 每个提醒都有具体行动按钮

**晚上卡片序列（18:00-22:00）：**

8. **日报卡片**
   - 今日数据总览 + 类别分布图
   - [查看完整时间线] 滚动到时间线

9. **AI点评卡片**
   - 3个亮点 + 1个建议
   - 建议附带行动按钮（接力到计划/设置）

10. **晚间仪式卡片**
    - 日记（AI预填数据摘要）
    - 明日计划（AI建议）
    - [晚安打卡] 结束一天

### 5.4 状态条设计

顶部状态条显示今日核心指标，但**不是冷冰冰的数字**，而是带有趋势和情感：

```
┌──────────────────────────────────────────────────────┐
│  🌙 晚上好，今天辛苦了              🐾 小透明 🌙 92分  │
├──────────────────────────────────────────────────────┤
│  ⏱ 有效 6.8h   🍅 8个   ✅ 3/3   📈 比昨天 +12%      │
│  ─────────────────────────────────────────────────   │
│  今日评分 92/100  ████████████████████░░  优秀       │
└──────────────────────────────────────────────────────┘
```

**今日评分**是一个综合分数，基于：
- 有效时间（40%）
- 任务完成率（25%）
- 专注质量/切换频率（20%）
- 习惯完成率（15%）

评分不是为了评判，而是为了给一个**直观的整体反馈**（类似睡眠评分），降低理解数据的认知负荷。

## 六、十条核心功能接力链

这是"一条龙"体验的核心机制。每条接力链都是一个**"触发→建议→行动→反馈"**的闭环。

### 接力链 1：晨报 → 今日计划 → 番茄钟

```
触发：早晨打开应用
  │
  ▼
晨报卡片显示AI建议："上午优先完成重构登录模块（你上午效率高37%）"
  │
  ▼ 用户点击[开始今天的计划]
今日计划卡片，任务已按AI建议排序
  │
  ▼ 用户点击[▶ 开始]
自动启动番茄钟（25分钟），关联该任务，进入专注模式
  │
  ▼ 番茄钟结束
自动记录任务耗时，提示下一个任务
```

**数据流转：**
- 晨报AI读取：`activities`（昨日数据）、`calendar_events`（今日日历）、`todos`（未完成任务）、`app_usage`（效率时段分析）
- 番茄钟写入：`pomodoro_sessions`（番茄钟记录）、关联 `todo_id`
- 番茄钟结束更新：`todos.actual_duration`、`todos.status`

**科学依据：** 执行意图（"上午做X"）+ 决策疲劳预防（AI排好优先级）+ 计划谬误纠正（历史数据估时）

---

### 接力链 2：日报异常 → AI分析 → 改进目标

```
触发：晚上日报生成，检测到异常数据
（如：微信使用时长超过P90，或专注时间连续3天下降）
  │
  ▼
日报卡片中异常数据点高亮（橙色下划线）
  │
  ▼ 用户点击异常数据点
展开AI分析卡片：
"微信今天2.3h，主要集中在14:00-16:00。
 这是你连续第3天下午微信使用上升。
 可能原因：下午注意力低谷时的逃避行为。
 建议：下午设置2个45分钟专注块，屏蔽微信。"
  │
  ▼ 用户点击[一键设置]
自动创建：
- 目标："下午专注时段"（连续5天）
- 习惯："下午番茄钟"（每日2个）
- 番茄钟模板：45分钟+屏蔽微信
- 排期：明天14:00开始
  │
  ▼ 次日14:00
宠物提醒："该开始下午专注了，番茄钟已准备好"
```

**数据流转：**
- 异常检测：统计 `activities` 中 category="摸鱼/社交" 的时长，与个人基线（P50/P90）对比
- 创建目标写入：`goals` 表
- 创建习惯写入：`habits` 表
- 番茄钟模板写入：`pomodoro_templates` 表
- 排期写入：`schedules` 表

**科学依据：** 习惯回路（提示=14:00，行为=番茄钟，奖赏=成就）+ 执行意图（"如果14:00，就开始番茄钟"）+ 数据驱动而非意志力

### 接力链 3：番茄钟分心 → 屏蔽干扰 → 恢复专注

```
触发：番茄钟进行中，检测到切换到干扰应用（微信/B站/抖音）超过2次
  │
  ▼
右上角弹出AI教练气泡（非阻塞，不打断当前工作）：
"你刚切到微信3次了。要我帮你屏蔽5分钟吗？"
  │
  ├─ 用户点击[屏蔽5分钟]
  │   → 浏览器扩展+系统hosts屏蔽干扰网站
  │   → 宠物显示"🛡️ 专注护盾已开启"
  │   → 5分钟后自动解除，询问是否延长
  │
  ├─ 用户点击[我在处理工作]
  │   → AI记录"微信=工作相关"，本次不再提醒
  │   → 优化未来的干扰判断模型
  │
  └─ 用户忽略
      → 30秒后气泡自动消失，不重复打扰
```

**数据流转：**
- 分心检测：`app_tracker` 实时获取前台应用，与 `distraction_apps` 列表对比
- 屏蔽操作：调用浏览器扩展API + Windows hosts文件
- 用户反馈写入：`user_feedback` 表（用于优化干扰判断）

**科学依据：** 注意力残留（每次切换损失15-25分钟）+ BJ Fogg模型（降低"屏蔽干扰"的能力门槛到一次点击）+ 自主感（用户可以选择"我在工作"而非被强制）

### 接力链 4：任务完成 → 耗时对比 → 估时优化

  │
  ▼
系统自动计算：

  │
  ▼

"🎉 比预估快了45分钟！
 你做'重构类'任务平均1h20m，下次可以参考这个时间。"
  │
  ├─ [继续下一个任务] → 接力到下一个待办
  ├─ [休息一下] → 设5分钟休息提醒
  └─ [记一笔] → 打开日记快速记录
```

**数据流转：**
- 读取：`todos.estimated_duration`、`pomodoro_sessions`（该任务的所有番茄钟）
- 计算：实际耗时 = Σ番茄钟时长
- 更新：`todos.actual_duration`、`user_task_type_stats`（按任务类型统计平均耗时）
- 未来估时：创建新任务时，AI根据任务类型和历史数据建议预估时间

**科学依据：** 计划谬误纠正（系统性低估任务时间，用历史数据校准）+ 胜任感（"比预估快"的正反馈）+ 蔡格尼克效应（完成后立即提示下一步）

**科学依据：** 执行意图（"周二上午做X"比"这周做X"执行率高）+ 计划谬误（周维度更明显，需要数据校准）+ 蔡格尼克效应（未完成任务移到下周，释放大脑内存）

**科学依据：** 目标设定理论（Locke & Latham：具体且有挑战的目标比"尽力而为"效果好）+ 习惯回路（提示=番茄钟模板，行为=45分钟专注，奖赏=宠物反馈/成就）+ 自我决定理论（胜任感来自看到进步曲线）

### 接力链 8：番茄钟结束 → 休息提醒 → 恢复提醒

```
触发：番茄钟完成（25/45分钟专注）
  │
  ▼
弹出休息卡片：
"☕ 休息5分钟吧。站起来走走，喝杯水。"
  │
  ▼ 5分钟倒计时开始
- 宠物显示"☕ 休息中"
- 如果用户在休息时间打开工作应用，宠物提示："还在休息时间，放松一下～"
- 喝水习惯打卡提醒
  │
  ▼ 5分钟到
宠物气泡："休息好了吗？准备开始下一个番茄钟？"
  │
  ├─ [▶ 开始下一个] → 启动新番茄钟，同任务或下一任务
  ├─ [再休息5分钟] → 延长休息
  └─ [今天到这] → 结束专注，回到主页
```

**科学依据：**
- ** ultradian rhythm（超昼夜节律）**：人的注意力以90-120分钟为周期波动，25分钟专注+5分钟休息匹配这个节律
- **积极休息的恢复效果**：站立/走动比继续看屏幕恢复效果好3倍（注意力恢复理论）
- **微习惯**：喝水打卡利用番茄钟休息的自然间隙，不需要额外意志力

- **蔡格尼克效应**：明日计划让大脑可以"放下"今天

## 七、AI 渗透层设计

### 7.1 核心理念：AI 是一层，不是一页

当前 AI 对话是一个独立页面（AIChat.tsx），用户必须主动切换。重构后，AI 以三种形态渗透在整个体验中：

```
┌─────────────────────────────────────────────────────┐
│                    AI 渗透的三种形态                   │
│                                                       │
│  1. 常驻对话栏（底部）                                │
│     用户随时可以问，AI知道当前页面上下文               │
│                                                       │
│  2. 场景化卡片（嵌入页面内容流）                       │
│     在日报/待办/番茄钟等场景中自动出现AI建议卡片       │
│                                                       │
│  3. 即时气泡（宠物/右上角）                           │
│     实时提醒、分心干预、成就通知                      │
│                                                       │
└─────────────────────────────────────────────────────┘
```

### 7.2 底部常驻 AI 对话栏

```
┌──────────────────────────────────────────────────────┐
│                                                        │
│  ... 页面内容 ...                                      │
│                                                        │
├──────────────────────────────────────────────────────┤
│  🤖 [💬 问我任何关于你今天的事...]        [📎] [↑]    │
└──────────────────────────────────────────────────────┘
```

**关键设计：**
- **全局常驻**：无论在哪个页面，底部都有对话栏
- **上下文感知**：AI 自动知道用户当前在看什么页面、什么数据
  - 在日报页面问"为什么微信这么多"→ AI 直接分析今日微信使用数据
  - 在周计划页面问"我该怎么安排"→ AI 基于效率数据建议排期
  - 在番茄钟页面问"我专注了多久"→ AI 回答当前番茄钟数据
- **快捷提问**：点击输入框显示上下文相关的建议问题
  - 日报页面："今天最大的问题是什么？" / "和昨天比怎么样？"
  - 计划页面："帮我排今天的优先级" / "这个任务要多久？"
- **AI 回复包含操作按钮**：AI 不只是说，还能直接做
  - "建议你设个番茄钟" → 按钮[设为25分钟番茄钟]
  - "这个任务可以拆成3步" → 按钮[一键拆分]
  - "明天下午效率低，建议安排会议" → 按钮[调整明日计划]

### 7.3 场景化 AI 触点清单

| 页面/场景 | AI 触点 | 触发时机 | AI 行为 |
|-----------|---------|---------|---------|
| 今日主页（早晨） | 晨报建议 | 早晨首次打开 | 基于昨日数据+今日日历给出今日建议 |
| 今日主页（计划） | 任务估时 | 创建/查看待办 | "类似任务你平均花1h20m，建议预估1.5h" |
| 今日主页（计划） | 优先级排序 | 添加多个任务后 | "根据截止日期和你的效率曲线，建议排序为..." |
| 番茄钟进行中 | 分心干预 | 切到干扰应用≥2次 | 温和提醒+一键屏蔽 |
| 番茄钟结束 | 专注质量点评 | 每个番茄钟结束 | "这段专注质量高/中/低，因为切换了N次" |
| 日报 | 异常检测 | 数据显著偏离基线 | 高亮异常+分析原因+建议行动 |
| 日报 | 每日点评 | 日报生成后 | 3亮点+1建议，建议带行动按钮 |
| 日记 | 预填+情感 | 打开日记卡片 | 预填今日数据摘要，写完后情感分析+宠物反馈 |
| 周计划 | 智能排期 | 任务分配到天时 | 基于效率时段数据建议排期 |
| 周报 | 周度复盘 | 周末 | 本周模式分析+下周建议 |
| 深度洞察 | 模式发现 | 积累2周数据后 | 学术框架分析+改进目标建议 |
| 目标 | 进度诊断 | 每周检查目标时 | "目标进度60%，剩余时间建议..." |
| 习惯 | 中断预警 | 习惯即将中断 | "你昨天没打卡，今天要继续吗？连续记录不要断" |
| 设置 | 配置建议 | 首次使用/修改设置 | "根据你的使用习惯，建议开启自适应采样" |

### 7.4 AI 回复中的操作按钮设计

AI 的回复不应该只是文字，而应该包含**可执行的操作按钮**。这是"AI 渗透层"与"功能接力链"的连接点。

操作按钮类型：

| 按钮类型 | 示例 | 点击后行为 |
|---------|------|-----------|
| 启动功能 | [开始番茄钟] | 直接启动番茄钟，不跳转页面 |
| 创建数据 | [创建待办] | 弹出创建表单，预填AI建议内容 |
| 修改设置 | [屏蔽微信5分钟] | 直接执行屏蔽操作 |
| 跳转页面 | [查看详情] | 跳转到相关页面并高亮对应数据 |
| 应用建议 | [应用到下周计划] | 批量执行AI建议的排期调整 |
| 确认/取消 | [好的] [不用了] | 确认或忽略AI建议 |

**设计原则：**
- 按钮最多3个，避免选择过载
- 主按钮（最推荐的行动）放最左边，高亮显示
- 永远有一个"忽略/不用了"选项，保持用户的自主感
- 操作执行后给即时确认反馈

## 八、成长反馈体系：四层反馈模型

人的行为改变需要不同时间尺度的反馈。本方案设计四层反馈，从秒级到月级，层层递进：

### 8.1 四层反馈架构

```
┌─────────────────────────────────────────────────────┐
│  L4 月级反馈：身份认同                                │
│  深度洞察 · 成长曲线 · 成就墙 · "我是一个专注的人"     │
│  ─────────────────────────────────────────────────  │
│  L3 周级反馈：模式认知                                │
│  周报 · 周度趋势 · 效率时段发现 · 目标进度             │
│  ─────────────────────────────────────────────────  │
│  L2 日级反馈：成就感                                  │
│  日报 · 今日评分 · AI点评 · 日记反思 · 成就解锁        │
│  ─────────────────────────────────────────────────  │
│  L1 即时反馈：状态感知                                │
│  宠物状态 · 番茄钟倒计时 · 分心提醒 · 打卡动画         │
└─────────────────────────────────────────────────────┘
```

### 8.2 L1 即时反馈（秒级~分钟级）

**目的**：让用户对"当下"有感知，拉回分心。

| 反馈元素 | 触发 | 表现 |
|---------|------|------|
| 宠物状态 | 活动分类变化 | "💻 正在写代码" / "💬 刚切到微信" / "☕ 已摸鱼18分钟" |
| 番茄钟倒计时 | 番茄钟进行中 | 圆环进度+剩余时间，颜色随时间变化 |
| 专注质量环 | 番茄钟进行中 | 实时计算切换频率，显示"深度专注/一般/分心" |
| 分心气泡 | 切到干扰应用 | 右上角温和提醒 |
| 打卡动画 | 习惯打卡 | 勾选动画+宠物表情变化 |
| 任务完成动画 | 待办完成 | 划线动画+轻微震动反馈 |

**设计原则**：
- 即时反馈要**轻量**，不打断工作流
- 宠物显示"摸鱼"时不做道德评判，只是陈述事实（"你看见它显示摸鱼的时候，会自动切回来"）
- 声音/震动可选，默认安静

### 8.3 L2 日级反馈（小时级~天级）

**目的**：给一天一个清晰的"终点感"和成就感。

| 反馈元素 | 时间 | 内容 |
|---------|------|------|
| 晨报 | 早晨 | 昨日回顾+今日建议，开启一天 |
| 上午小结 | 午休时 | 上午数据+下午计划 |
| 日报 | 晚上 | 完整数据总览+分类时间 |
| AI点评 | 日报后 | 3亮点+1建议 |
| 今日评分 | 晚上 | 综合评分（0-100） |
| 日记 | 晚上 | AI预填+情感反馈 |
| 成就解锁 | 随时 | 满足条件时弹出 |

**设计原则**：
- 日报以**亮点为主**（3个亮点 vs 1个建议），避免羞耻感
- 今日评分是**自我比较**（与昨天的自己比），不是社会比较
- 日记是反思而非检讨，AI 预填降低门槛

### 8.4 L3 周级反馈（周级）

**目的**：发现模式，调整策略。

| 反馈元素 | 内容 |
|---------|------|
| 周报 | 本周数据总览+趋势+任务完成率 |
| 效率时段分析 | 你在什么时间效率最高 |
| 周度对比 | 与上周对比，进步/退步 |
| 目标进度 | 本周目标完成情况 |
| 习惯连续天数 | 本周习惯打卡率 |
| 下周建议 | AI基于本周数据建议下周重点 |

**设计原则**：
- 周级反馈关注**模式**而非单日波动（单日数据有噪音，周级才有统计意义）
- 用"发现"而非"批评"的语气："我发现你周三效率最低"而非"你周三表现差"

### 8.5 L4 月级反馈（月级~长期）

**目的**：建立身份认同，看到长期成长。

| 反馈元素 | 内容 |
|---------|------|
| 深度洞察 | 基于学术框架的量化分析 |
| 成长曲线 | 有效时间/专注质量/任务完成率的月度趋势 |
| 成就墙 | 所有已解锁成就 |
| 年度报告 | 类似Spotify Wrapped的年度回顾 |
| 行为画像 | "你是一个晨型深度工作者" |

**设计原则**：
- 长期反馈的核心是**身份认同**——不是"我今天做了什么"，而是"我是什么样的人"
- 成长曲线要展示**进步趋势**，即使绝对值不高，上升趋势本身就是激励
- 成就和画像基于真实数据，不可刷

## 九、桌面宠物重定位：从玩具到状态中枢

### 9.1 新定位

当前宠物主要是状态显示。重构后，宠物是**整个系统的轻量化入口和情感载体**：

- **状态显示**：实时显示当前活动（已有）
- **迷你控制台**：点击宠物展开快捷操作面板
- **情感载体**：宠物情绪随用户行为变化，建立情感连接
- **提醒通道**：AI教练提醒、成就通知通过宠物气泡传达

### 9.3 宠物情绪模型

宠物情绪基于多维度实时计算：

| 维度 | 数据来源 | 影响 |
|------|---------|------|
| 专注度 | 当前番茄钟状态/切换频率 | 专注时宠物认真工作，分心时宠物困惑 |
| 成就感 | 今日任务完成数/成就解锁 | 完成任务时宠物开心，解锁成就时庆祝 |
| 疲劳度 | 连续工作时长/休息间隔 | 连续工作太久宠物显示疲惫，提示休息 |
| 习惯健康度 | 今日习惯完成率 | 喝水/运动打卡后宠物活力增加 |
| 时间节律 | 当前时段 | 早晨精神、午后慵懒、晚上困倦 |

**设计原则**：
- 宠物情绪是**镜子**，反映用户状态，不是评判者
- 不使用负面情绪（如愤怒/失望），只用中性到积极的情绪
- 宠物"疲惫"时提示休息，是关心而非催促

- AI思考中："正在结合你的历史数据找模式..."
- 周报生成中："正在汇总你本周的 47 个番茄钟..."

AI分析失败时：
```

不影响记录，我会在下次截图时重试。

- 页面切换：淡入淡出（200ms），不使用滑动等大幅动画
- 时间线更新：新活动从顶部滑入（300ms ease-out）
- 番茄钟倒计时：圆环平滑过渡
- 成就解锁：庆祝动画（粒子+缩放，2秒，可跳过）
- 宠物状态变化：平滑过渡表情/动作（500ms）
- 接力链卡片展开：从触发点展开（300ms），保持空间连续性

### 11.2 后端架构

#### 接力链引擎

新增 `relay_engine.py`，负责接力链的触发和推荐：

```python
"""
接力链引擎：根据用户状态和事件，推荐下一步行动。

核心概念：
- Trigger（触发条件）：什么事件/状态触发这条接力链
- Condition（条件判断）：进一步判断是否应该推荐
- Action（推荐行动）：推荐用户做什么
- Context（上下文数据）：执行行动时需要的数据
"""

class RelayTrigger(Enum):
    MORNING_BRIEF = "morning_brief"           # 早晨打开应用
    TASK_STARTED = "task_started"             # 任务开始
    TASK_COMPLETED = "task_completed"         # 任务完成
    POMODORO_DISTRACTION = "pomodoro_distraction"  # 番茄钟分心
    POMODORO_COMPLETED = "pomodoro_completed"      # 番茄钟完成
    REPORT_ANOMALY = "report_anomaly"         # 日报异常
    INSIGHT_DISCOVERED = "insight_discovered" # 新洞察
    MEETING_SOON = "meeting_soon"             # 会议即将开始
    MEETING_ENDED = "meeting_ended"           # 会议结束
    EVENING_REVIEW = "evening_review"         # 晚间复盘
    HABIT_STREAK_RISK = "habit_streak_risk"   # 习惯连续中断风险
    ACHIEVEMENT_UNLOCKED = "achievement_unlocked"  # 成就解锁

class RelayEngine:
    """接力链引擎：监听事件，匹配接力链，推送推荐"""

    def __init__(self, event_bus, db):
        self.event_bus = event_bus
        self.db = db
        self.relays = self._register_relays()

    def _register_relays(self):
        return [
            MorningBriefRelay(),
            TaskToPomodoroRelay(),
            DistractionShieldRelay(),
            TaskCompleteFeedbackRelay(),
            ReportAnomalyRelay(),
            InsightToGoalRelay(),
            MeetingPrepRelay(),
            PomodoroBreakRelay(),
            EveningDiaryRelay(),
            AchievementRelay(),
        ]

    def on_event(self, event: RelayEvent):
        """事件发生时，匹配并触发接力链"""
        for relay in self.relays:
            if relay.matches(event):
                if relay.should_trigger(self.db, event):
                    action = relay.build_action(self.db, event)
                    # 通过SSE推送到前端
                    self.event_bus.push_event('relay_trigger', action)
```

每条接力链实现一个基类：

```python
class BaseRelay:
    trigger: RelayTrigger

    def matches(self, event: RelayEvent) -> bool:
        """判断事件是否匹配这条接力链"""
        return event.type == self.trigger

    def should_trigger(self, db, event: RelayEvent) -> bool:
        """进一步条件判断（如频率控制、用户偏好）"""
        return True

    def build_action(self, db, event: RelayEvent) -> dict:
        """构建推荐行动数据（推送给前端渲染卡片）"""
        raise NotImplementedError
```

    id INTEGER PRIMARY KEY,
    event_id TEXT,                     -- 日历事件ID
    activity_id INTEGER,               -- 关联活动记录
    title TEXT,
    notes TEXT,                        -- 笔记内容
    decisions TEXT,                    -- 关键决策（JSON数组）
    action_items TEXT,                 -- 待办事项（JSON数组）
    created_at TEXT NOT NULL,
    FOREIGN KEY (activity_id) REFERENCES activities(id)
);

-- 任务类型统计（用于AI估时）
CREATE TABLE task_type_stats (
    id INTEGER PRIMARY KEY,
    task_type TEXT NOT NULL,           -- 任务类型（重构/文档/会议...）
    avg_duration_sec INTEGER,          -- 平均耗时
    median_duration_sec INTEGER,       -- 中位数耗时
    sample_count INTEGER,              -- 样本数
    updated_at TEXT NOT NULL
);

-- 宠物状态
CREATE TABLE pet_state (
    id INTEGER PRIMARY KEY DEFAULT 1,
    name TEXT DEFAULT '小透明',
    level INTEGER DEFAULT 1,
    exp INTEGER DEFAULT 0,
    mood TEXT DEFAULT 'neutral',       -- 情绪状态
    outfit TEXT,                       -- 装备/外观
    last_interaction TEXT,
    updated_at TEXT NOT NULL

## 十三、附录：设计决策与科学依据对照表

| 设计决策 | 科学依据 | 解决的问题 |
|---------|---------|-----------|
| 时间线作为主页 | 认知负荷理论、图式理论（人对时间的线性认知图式） | 功能平铺导致的外在认知负荷 |
| 下一步行动建议 | 执行意图理论、决策疲劳研究 | 用户不知道接下来干什么 |
| 数据点可点击行动 | BJ Fogg行为模型（降低能力门槛） | 看到问题但不知道怎么改 |
| AI常驻底部而非独立页 | 情境认知理论（认知在情境中发生） | AI是孤岛，不在需要时出现 |
| 番茄钟25/45分钟 | 超昼夜节律、注意力残留研究 | 频繁切换导致的效率损失 |
| 晨报+晚间日报 | 峰终定律 | 体验没有明确的起点和终点感 |
| AI预填日记 | 表达性写作研究、BJ Fogg模型（降低启动门槛） | 面对空白页写不出来 |
| 3亮点+1建议 | 积极比率（Losada 3:1）、成长型思维 | 反馈变成批评导致放弃 |
| 宠物情绪反映状态 | 社会促进效应、情感化设计（Norman） | 数据冰冷缺乏情感连接 |
| 今日评分 | 反馈心理学、自我效能感 | 数字太多缺乏整体感知 |
| 成就基于真实数据 | 自我决定理论（胜任感需真实） | 刷成就失去意义 |
| 周度模式而非单日 | 统计学（单日噪音大）、模式识别 | 单日波动导致误判 |
| 自主选择（永远有"不用了"） | 自我决定理论（自主感） | 强制建议引发逆反 |
| 接力链频率控制 | 习惯化（重复刺激导致反应减弱）、通知疲劳 | 太多提醒变成噪音 |
| 任务估时基于历史 | 计划谬误研究 | 系统性低估时间 |
| 未完成任务移到下周 | 蔡格尼克效应、GTD | 未完成事项占用大脑 |
| 下午低谷建议轻量任务 | 昼夜节律研究 | 下午强迫专注适得其反 |
| 休息时不记录不催促 | 注意力恢复理论 | 没有真正的休息 |
| 接力链而非独立功能 | 习惯回路（提示→行为→奖赏闭环） | 功能之间断裂 |
| 1+3+N导航 | 米勒定律（7±2）、信息架构 | 40+入口导致选择过载 |

---

> **最后一句话**：好的产品不是功能更多，而是**让用户在正确的时间看到正确的东西，做正确的事，并且感觉是自己在掌控**。ChallengeDaily 已经有了最好的地基——全自动数据采集。现在要做的是在这个地基上建一条流畅的"高速公路"，让数据自然地流向洞察，洞察自然地流向行动，行动自然地带来成长。
