# ChallengeDaily 答辩话术模板

> 适用场景：大学生课程大作业 / 毕设答辩 / 项目展示
> 受众：教师、评委、同学
> 策略：从商业场景切入 → 技术架构 → 亮点展示 → 稳健收尾

---

## Q1：请介绍一下你的项目

**推荐回答（1分钟版）**：

ChallangeDaily 是一款面向 Windows 用户的 AI 智能工作日报助手。它的核心流程是：自动截屏 → AI 视觉识别屏幕内容 → 分类到 12 种工作类型 → 最终自动生成 Markdown 日报，全程无需手动操作。

项目采用 Electron + React 18 + Flask 3 全栈架构，数据库用 SQLite WAL 模式，AI 层支持 OpenAI 兼容协议，默认接智谱 GLM-4V。目前已完成 22 个 API 模块、100+ 接口、23 张数据库表的设计，并通过 3 轮深度审计修复了 30+ 项问题。

---

## Q2：这个项目解决了什么实际问题？

**推荐回答**：

三个痛点：
1. **日报遗忘**：上班族经常忘记一天做了什么，手动补写日报耗时且不准确
2. **数据盲区**：不知道自己时间花在哪里，没有量化数据支撑效率优化
3. **隐私焦虑**：市面上同类软件隐私问题严重，用户不敢用

我们的方案：截图分析完立即删除 + Windows DPAPI 加密 API Key + 本地 SQLite 存储，数据完全不离开用户电脑。

## Q3：系统架构是怎样的？

**推荐回答**：

```
Electron 桌面壳
  ├── React 18 + TypeScript 前端（SPA，23 个页面）
  │   ├── 全局快捷键 / 系统托盘 / 桌面宠物
  │   └── 通过本地 HTTP API（127.0.0.1:58888）通信
  └── Python 后端（Flask 3 + Waitress WSGI）
      ├── 采集层：mss 截图 + Win32 API 窗口追踪
      ├── AI 层：OpenAI Vision SDK（兼容协议）
      ├── 业务层：22 个 Flask 蓝图模块
      └── 存储层：SQLite WAL 模式 + DPAPI 加密
```

## Q4：AI 是如何工作的？为什么能无 API Key 也能用？

**推荐回答（关键技术亮点）**：

我们的 AI 架构设计了**双模降级**策略：
- 有 API Key 时：截图 → AI Vision 模型识别工作内容 → 精准分类 + 摘要
- 无 API Key 时：Win32 获取前台窗口标题 → 内置 30+ 应用规则匹配 → 规则分类

这个设计保证了零配置可用，同时接入 Key 后体验飞跃。AI 兼容 OpenAI 协议，可接入智谱 GLM-4V / DeepSeek / Qwen / Kimi 等。

## Q5：多窗口场景怎么处理？

**推荐回答**：

通过 Win32 API 枚举所有可见窗口，计算每个窗口的屏幕占用面积，按面积比例分摊时间。闲置检测通过 Win32 的 GetLastInputInfo API，3 分钟无键鼠操作自动暂停采集，确保数据不被闲置时间污染。

---

## Q6：数据库设计有什么特点？

**推荐回答**：

23 张表，核心设计要点：
1. **WAL 模式**：读写并发不阻塞，适合高频插入场景（每 60 秒一次记录）
2. **Schema 版本管理**：自研迁移逻辑，兼容未来升级
3. **隐私优先**：API Key 存储用 Windows DPAPI 加密，不以明文落盘
4. **自动备份**：定时备份数据库，滚动保留 3 份

## Q8：遇到的最大技术挑战是什么？

**推荐回答**：

私有 API Key 的安全存储。最初用 .env 明文存储，安全隐患大。后来调研了 Windows DPAPI（数据保护 API），利用操作系统级别的用户密钥加密存储 API Key 到 vault.dat，只有当前 Windows 用户能解密。相比于 .env 文件、注册表、环境变量等方案，DPAPI 是 Windows 桌面应用最安全的本地密钥存储方案。
